# Game Dev Skills

可独立使用的游戏开发 Agent Skills。目录参考 `obsidian-skills`：每个技能位于 `skills/<skill-name>/`，包含 `SKILL.md` 和按需读取的参考文档。

## 技能

| 技能 | 用途 |
| --- | --- |
| [web-game-ui-dev](skills/web-game-ui-dev/SKILL.md) | 设计、实现、审查和调试浏览器游戏 UI，覆盖场景、布局、交互、动画、资源、本地化和验证。 |
| [game-test-dev](skills/game-test-dev/SKILL.md) | 编写、审查和修复玩法、前端、合同及服务测试，使用合成夹具和稳定断言覆盖回归风险。 |

## 使用

将所需的 `skills/<skill-name>/` 整个目录复制到目标工具配置的技能目录。保留 `references/` 和 `agents/`，不要只复制 `SKILL.md`。支持显式技能调用的工具可使用 `$web-game-ui-dev` 或 `$game-test-dev`。两个技能可以分别安装。

示例请求：

```text
使用 $web-game-ui-dev，为现有游戏增加目标选择面板。
复用现有玩法预览 API，保留当前布局体系，只验证相关稳定交互。
```

```text
使用 $game-test-dev，为这个规则补充回归测试。
用最小合成配置覆盖执行、预览一致性和非法输入，不绑定生产卡表。
```

`.claude-plugin/` 提供本地插件和 marketplace 元数据。它指向本仓库中的技能，不依赖远程仓库地址。

## 独立使用范围

UI 技能由已有 Web Game UI 技能及其多层工程规范整理而来。测试技能基于 `testing.md` 和 `common-mistakes.md`，提炼测试分层、内容与机制隔离、生命周期回归及环境隔离。使用时不需要原仓库、私有包或其他技能。

| 原规范层级 | 本技能保留的内容 |
| --- | --- |
| 工作原则及根规范 | 改动范围、依赖边界、玩法归属、稳定测试、本地化 |
| 前端家族规范 | 控制器与展示分离、场景层级、组件样式归属、存储与交互 |
| 共享前端规范 | 布局模式、坐标转换、弹层挂载、展示时钟、生命周期 |
| 游戏局部规范 | 可复用的拖拽、Canvas、动画锚点、资源清单和调试方法 |

游戏名称、具体路由、内容 ID、字体、分辨率、资源路径和私有 API 不属于技能要求。目标项目已有规范优先；没有规范时，采用技能中的通用默认值。技能不要求更换框架，也不要求新增场景编辑器、后端或全套运行时。

## 维护

- `SKILL.md` 只保留适用范围、核心边界、工作流程和参考文档入口。
- 详细规则按主题放入 `references/`，链接保持在技能目录内。
- 新增规则时区分通用约束、可选实现和具体产品决策。
- 修改技能名称或能力范围时，同步入口、UI 元数据和插件描述。
- 发布前检查 frontmatter、相对链接、JSON/YAML 元数据和独立复制后的可读性。
